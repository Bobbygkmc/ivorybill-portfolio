# Brand Guidelines

This is the lightweight brand source for `dev.uyammadu.com`. The fuller
site blueprint remains in `docs/SITE_BLUEPRINT.md`; this file gives
brand and asset tools a stable place to extract practical constraints.

## Positioning

Uyammadu Dev Services is a veteran-owned technical operator practice for
small businesses, restaurants, professionals, and builders who need
practical systems help. The site should feel trustworthy, local,
operator-led, and technically competent without becoming a generic agency
template.

### Brand Personality

| Trait | Meaning |
| --- | --- |
| **Practical** | Explain what works, what is risky, and what the owner receives. |
| **Technical** | Show systems proof, infrastructure awareness, and implementation detail. |
| **Plainspoken** | Avoid buzzword-heavy promises and vague transformation language. |
| **Trustworthy** | Keep statuses honest and privacy boundaries visible. |
| **Local** | Speak to real small-business operations, not abstract enterprise theater. |

### Core Attributes

| Attribute | Description |
| --- | --- |
| **Operator-first** | Every visual and page should support assessment, build, handoff, and proof. |
| **Privacy-aware** | Do not expose customer data, secrets, private footage, or internal records. |
| **Static and durable** | Prefer lightweight HTML/CSS/SVG assets over heavy dependencies. |
| **Proof-led** | Use project status, case studies, and lab work as evidence. |

## Visual System

- Use original SVGs, line-art diagrams, abstract dashboards, and device
  silhouettes before stock photography.
- Project thumbnails should use stable aspect ratios and no private data.
- Open Graph imagery should keep critical text in the central safe area
  and export to PNG later if platform testing requires it.
- Real photos and screenshots must follow `docs/MEDIA_CAPTURE_PLAN.md`.

### Prohibited

| Avoid | Reason |
| --- | --- |
| Guaranteed outcomes | Overclaiming and legal risk |
| Official partner claims | Implies endorsements that may not exist |
| Fake client names | Reduces trust |
| Private customer data | Privacy and security risk |
| Passwords or API keys | Security risk |
| Brand-heavy stock photos | Trademark and implied endorsement risk |
