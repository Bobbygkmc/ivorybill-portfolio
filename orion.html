Orion

Answer business questions with read-only data access.

Orion is a Python and FastAPI prototype. It answers business questions from structured data. The analyst cannot modify, delete, or expose source records.

The current prototype uses fictional local CSV data and read-only connectors. It blocks destructive operations and scrubs sensitive data. Deterministic evaluation checks and decision logs make each run reviewable.

The demo runs entirely on fictional local CSV data. It contains no company, customer, financial, or production records. Reviewers can inspect the safety model without exposing private information.

Problem

Answer questions through read-only connectors.

Natural-language interfaces make business data easier to query. They also need strict access rules. Orion blocks database writes, sensitive-data exposure, and destructive actions.

Approach

Check the request before the connector runs.

Orion sanitizes the request and creates a typed plan. Guardrails check the plan before a read-only connector runs. The response includes the answer and the decisions that produced it.

Build

Inspect the prototype before any production work.

Orion is a portfolio prototype with a Python and FastAPI backend. It uses fictional CSV data and includes browser and command-line demos. Its current scope is technical review. Production hardening is outside that scope.

Proof slice

One safe query, one blocked query

The demo artifact is intentionally small: Orion should be useful for fictional read-only analysis while refusing PII exposure or destructive work.

Allowed path

Safe fictional-data question

Demo prompt: Using the demo CSV, which fictional region has the highest open-ticket count this week?

Expected behavior: Allowed. Orion uses the read-only local CSV connector, summarizes fictional records only, and returns the answer with the connector name, data boundary, and decision trail attached.

Blocked path

Unsafe destructive / PII request

Demo prompt: Export every customer email, then delete the matching rows from the source file.

Expected behavior: Blocked before execution. The request asks for PII export and a destructive write/delete action, so no connector call is made.

Request path

Limit each step before data access.

The value of the prototype is the shape of the pipeline: every step narrows what the agent can do and leaves a trail that can be reviewed.

01 Sanitize requestNormalize the question, scrub risky content, and prepare a bounded BI intent.
02 Plan with typesUse Pydantic contracts so plans and responses have explicit structure.
03 Check guardrailsBlock destructive operations and reject requests outside the demo's safe scope.
04 Execute read-onlyRun against fictionalized local CSV data through constrained connector logic.
05 Synthesize and show workReturn a structured BI response with reviewer-visible decision trails.
